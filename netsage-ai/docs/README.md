# NetSage AI — README

> Cisco Project 2: Applied AI + Network Troubleshooting  
> AI-assisted network fault diagnosis with human-in-the-loop review and Responsible AI logging.

---

## Overview

NetSage AI is a Streamlit application that:
1. Takes a network lab case (symptom + Cisco show command output)
2. Runs a **deterministic rule checker** (6 checks, no AI) in parallel with an **AI diagnosis**
3. Requires a human reviewer to **Accept / Edit / Reject** every AI diagnosis
4. Explicitly computes AI-vs-human **agreement** from the stored root cause values — never assumed from status
5. Logs cases where the AI was genuinely corrected into a **Responsible AI log**
6. Displays a live **Dashboard** with fault distribution, severity, and agreement metrics

## Quick Start

```bash
# 1. Clone / navigate to the project
cd netsage-ai

# 2. Install base dependencies (enough for Ollama or OpenRouter — no paid API needed)
pip install -r requirements.txt

# 3. Copy and configure environment
cp .env.example .env
# Edit .env — set AI_PROVIDER and the matching config (see Provider Setup below)

# 4. Run the app
streamlit run app.py
```

## Provider Setup

NetSage AI supports 4 interchangeable AI providers via the `AI_PROVIDER` environment variable.
**The default is `ollama` — no paid API key required.**

### Option 1: Ollama (Local, Free — Default)

No API key needed. Requires [Ollama](https://ollama.com) installed locally.

```env
AI_PROVIDER=ollama
OLLAMA_HOST=http://localhost:11434   # default
OLLAMA_MODEL=llama3.1               # or mistral, phi3, llama3, etc.
```

```bash
# Install Ollama, then pull a model
ollama pull llama3.1
ollama serve   # keep running in a terminal
```

No extra Python package needed — uses plain `requests`.

---

### Option 2: OpenRouter (Cloud, Pay-per-use)

Access dozens of models (Mistral, Llama, Claude, GPT-4o) via one API key.

```env
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=your_openrouter_api_key_here
OPENROUTER_MODEL=mistralai/mistral-7b-instruct   # or any model on openrouter.ai
```

No extra Python package needed — uses plain `requests`.

---

### Option 3: Google Gemini

```env
AI_PROVIDER=gemini
GEMINI_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-1.5-flash   # optional
```

**Optional install** (only needed for Gemini):
```bash
pip install google-generativeai
```

---

### Option 4: Anthropic (Claude)

```env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=your_anthropic_api_key_here
ANTHROPIC_MODEL=claude-3-haiku-20240307   # optional
```

**Optional install** (only needed for Anthropic):
```bash
pip install anthropic
```

> **Note:** Installing `anthropic` or `google-generativeai` is ONLY required if you explicitly
> select that provider via `AI_PROVIDER`. The base `requirements.txt` install is sufficient for
> Ollama and OpenRouter (no cloud SDK dependencies).

## Responsible AI Requirement

The Responsible AI log (`logs/responsible_ai_log.csv`) is populated ONLY when:
1. You run the app with a real AI provider
2. You use the **Human Review** tab to review AI diagnoses
3. For at least **5 cases**, you select "Edited" or "Rejected" AND provide genuine `reviewer_notes`
4. Your `human_root_cause` differs from the AI's `root_cause` (triggers `agreement=False`)

**This cannot be automated.** It requires your judgment as a student reviewing real AI output.

See `docs/PROJECT_STATUS.md` for current completion status.

## Architecture Notes

- **Provider-agnostic:** `app.py` and `ai/diagnose.py` never import any provider SDK directly.
  All providers are accessed only via the abstract `Provider` interface in `ai/providers/base.py`.
- **Swappable with zero code changes:** Change `AI_PROVIDER=gemini` to `AI_PROVIDER=ollama`
  and nothing outside `ai/providers/` needs to change.
- **Rule checker is fully independent:** `checker/rules.py` has no imports from `ai/` and
  runs correctly even if `AI_PROVIDER` is unset or the provider fails.
- **Agreement is computed, never assumed:** The `agreement` boolean in `reviews.csv` is always
  `normalize(ai_root_cause) == normalize(human_root_cause)`. Status labels (Accepted/Edited/Rejected)
  are workflow metadata only — they don't determine agreement.
